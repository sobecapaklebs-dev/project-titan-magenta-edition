# Titan Open-Source Readiness — BuildFix29

BuildFix29 prepares the source tree for a future public release; it does **not** publish the project.

## Release-safety gate

Run:

```sh
python3 kernel/tools/titan_source_audit.py .
```

The audit is fail-closed for unapproved ROM/disc images, key/certificate containers, private-key/token signatures and unexplained binary payloads. Third-party areas used by the shipped tree must retain their license/provenance material.

Project-owned generated fixtures and reviewed third-party bootstrap payloads are explicitly identity-locked:

- `apps/project-nes/data/roms/ProjectNesTest.nes` — Project Titan-owned deterministic diagnostic NES ROM, generated by `apps/project-nes/tools/make_test_rom.py` and covered by `apps/project-nes/LICENSE`.
- `kernel/src/graphics/vu1/titan_wave_vu1_micro.bin` — generated VU1 microprogram; human-readable source is `kernel/src/graphics/vu1/titan_wave_vu1.vsm` and the kernel Makefile contains the generation path.

The BF30 FMCB integration additionally allowlists only the exact upstream ELF/IRX payload identities imported from the user-supplied FMCB archive. Each such entry requires `BUILDFIX30_FMCB_PROVENANCE.md` and the retained upstream README; a hash change fails closed and requires deliberate review. This is a provenance/integrity control, not a substitute for final redistribution-license review. Commercial ROMs, disc images, keys, credentials and private assets are not permitted in a public source bundle.

## Third-party provenance

The gate explicitly requires provenance/license material for the frozen FCEUmm vendor tree, BearSSL PS2 integration, Titan-Neutrino, Titan UL and the GoldenEye/mgb64 development material. This is not a substitute for a final legal review; it prevents accidental loss of the notices already required by the source tree.

## Generated and private material

Generated host objects, build directories, caches and packaging junk are excluded from source releases. Private showcase artwork/themes belong outside a public source bundle unless their redistribution rights are independently cleared.

## Contributor paths

`CONTRIBUTING.md` defines a High/Mid/Advanced path. Beginner contributors can remain on Titan Application SDK + normalized services. Advanced contributors can work through TGR/runtime contracts without depending on private pikaVR/Vlombis implementation symbols.
