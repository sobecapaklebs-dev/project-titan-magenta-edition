Project Titan Magenta Edition — P10.6
Persistent Controller Session / Player Assignment / Multitap

Implemented:
- Bluetooth runtime request begins asynchronously on entry to Health & Safety.
- Startup reconnect operates only on already-paired controller records; no boot discovery scan.
- Player 1..4 preferences persist by stable_key + device type + transport.
- Player 1 owns shell navigation when available; temporary fallback never destroys the persisted preference.
- Welcome glyph remains device-derived: DS2=X, Sony modern=PS, Xbox=HOME.
- Settings > Accessories now contains Wireless Accessories, Controller Assignment and Multitap.
- Controller Assignment cycles connected inputs or Automatic for P1..P4.
- Multitap setting is persisted and passed to Titan UL using established OPL PADEMU bits 24/25.
- Titan transport-only remains bit23 and is not reused for Multitap.
- Assignment writes are transactional and run only on TitanStorageScheduler.

Important scope boundary:
- The shell/Native App logical assignment is stable and persistent.
- Legacy OPL PADEMU exposes one selected modern transport per game session. P10.6 does not pretend that mixed USB+BT modern controllers have a new game-time stable-key ordering ABI.
- Four logical Titan players are supported in this front; no unsupported 8-player claim is introduced.

Hardware validation still required after target build.
